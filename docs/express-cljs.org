* Introduction
express-cljs is a ClojureScript (Node.js) binding of [[https://expressjs.com][Express 5]] for HTTP
APIs, of the [[https://github.com/websockets/ws][ws]] package for WebSockets on the same HTTP server, and of a
JSON-RPC 2.0 layer that serves ONE method registry over both transports (a single
=POST /rpc= endpoint and websocket text frames). Everything a caller touches is
ClojureScript data: kebab-case option maps in, kebab-case request / response /
connection / frame maps out, promesa promises for every asynchronous operation,
core.async channels for websocket messages and lifecycle events.

The architecture is self-contained and deliberately thin:

- =express-cljs.core= — the Express / Node binding: application and =http.Server=
  lifecycle, request → map and map → response translation, cookies (with Node-crypto
  signing), body parsers, static files, the error chain and renderer, graceful
  =close!=.
- =express-cljs.ws= — the =ws= binding: one =upgrade= listener per server,
  pre-handshake authentication, connection maps with IN / OUT channels, topics,
  broadcast, keepalive, the shutdown choreography, and a client (=connect!=).
- =express-cljs.route= — routing as data (pure).
- =express-cljs.middleware= — body-parser / static descriptors and Ring-style
  wrappers (pure).
- =express-cljs.rpc= — JSON-RPC 2.0 frames, registry, dispatch, HTTP routes,
  websocket serving, notifications, client (pure: JSON goes through =ws=).
- =express-cljs.util= — case translation, header policy, option validation, the
  error constructors and the RPC error table (pure).

Only =core= and =ws= contain JavaScript interop (house style: =js-invoke= +
=goog.object=, no =^js= hints, no dot-forms). Runtime npm dependencies: =express=
and =ws=, nothing else. The research behind every decision, with evidence, is
=docs/express-api-inventory.org= (section numbers quoted in docstrings and below
point there).

* Quick start
#+begin_src clojure
(require '[express-cljs.core :as core]
         '[express-cljs.route :as route]
         '[express-cljs.middleware :as mw]
         '[express-cljs.ws :as ws]
         '[express-cljs.rpc :as rpc]
         '[promesa.core :as p]
         '[cljs.core.async :as async :refer [<! go-loop]])

;; HTTP: handlers are (fn [req-map] -> response-map | nil | promise)
(def app
  (core/app {:env :production :trust-proxy :loopback :cookie-secret "s3cret" :json true}
    {:use  [(mw/request-id)]
     :get  {"/health"     (fn [_] {:body {:ok true}})
            "/users/:id"  (fn [{:keys [params]}]
                            (p/let [u (find-user (:id params))]
                              (if u {:body u} (throw (core/http-error 404 "no such user")))))}
     :post {"/users"      (fn [{:keys [body]}] {:status 201 :body (create-user! body)})}}
    ;; RPC over HTTP: POST /rpc
    (rpc/http-routes methods {:context (fn [req] {:user (get-in req [:headers :x-user])})})))

;; one registry for both transports
(def methods
  (rpc/registry {"math/add" (fn [{:keys [a b]} _ctx] (+ a b))
                 "jobs/run" (fn [params {:keys [notify! id]}]
                              (p/do (when notify! (notify! "jobs/progress" {:id id :pct 50}))
                                    {:done true}))}))

(p/let [server (core/listen! app {:port 8080 :host "127.0.0.1"})
        ;; one websocket endpoint, authenticated before the handshake
        wsv    (ws/serve! server {:path "/ws" :max-payload 1048576 :keepalive-ms 30000
                                  :authenticate (fn [{:keys [headers]}]
                                                  (when-let [tok (:x-auth headers)] {:user (verify tok)}))})]
  ;; raw frames: one IN channel per connection
  (ws/on-open! wsv (fn [conn]
                     (go-loop []
                       (when-let [m (<! (ws/messages conn))]
                         (ws/send! conn (str "echo " (:data m)))
                         (recur)))))
  ;; ... or JSON-RPC on another endpoint
  (rpc/serve-ws! (ws/serve! server {:path "/rpc-ws"}) methods)
  ;; shutdown: ws 1001 to every client, server.close, deadlines
  (js/process.on "SIGTERM" #(core/close! server {:timeout-ms 5000 :ws-close-timeout-ms 2000})))
#+end_src

Build with shadow-cljs (=:node-script= / =:node-library= targets); =express= and =ws=
are required at runtime from =node_modules=. The dependency on promesa is pinned to
12.0.1 with a vendored one-line patch (see [[*Design decisions][Design decisions]]).

* Core: application, server, request map, response map
** The app
=(core/app opts & route-sources)= builds an Express 5 application. Route sources
(tables, =route/routes= bundles, entries, vectors of those) are registered in
argument order (chapter [[*Routing as data][Routing as data]]). Options (kebab, =?= suffix
optional on booleans):

| Option | Meaning |
|--------+---------|
| =:env= | =:production= / =:development= / =:test= (Express 'env'; =:test= silences the 5xx console log) |
| =:trust-proxy= | =false= (default), =true=, hop count, =:loopback= / =:linklocal= / =:uniquelocal=, a CIDR string, a vector, or =(fn [ip i])= |
| =:x-powered-by?= | default =false= (Express's default is =true=) |
| =:case-sensitive-routing?= =:strict-routing?= | router flags |
| =:query-parser= | =:simple= (default), =:extended=, =false= or a fn |
| =:etag= | =:weak= (default), =:strong=, =false= |
| =:json-escape?= =:json-replacer= =:json-spaces= =:subdomain-offset= | Express settings |
| =:cookie-secret= | enables =:signed-cookies= on the request map and ={:signed? true}= cookies |
| =:expose-errors?= | show messages of non-http errors (default: true unless =:env= is =:production=) |
| =:on-error= | =(fn [err req-map])= called for every rendered error (replaces the console log) |
| =:error-handler= | =(fn [err req-map] -> response | nil)=, an app-wide error handler run before the renderer |
| =:json= =:urlencoded= =:text= =:raw= | =true= or an option map: mounts that body parser globally before the routes |
| =:json-limit= | shorthand for ={:json {:limit ..}}= |

Settings can be read and written later with =core/setting= / =core/set-setting!=.
=core/mount-upstream!= appends a caller-supplied Express middleware function after
the routes (before =listen!=); for middleware that must run first put
=(route/use (route/upstream f))= in the route data (pitfall 9.29).

** listen! and the server handle
=(core/listen! app {:port 0 :host "127.0.0.1"})= creates the =http.Server= itself
(so the wrapper owns the =upgrade= event and the timeouts) and resolves with a
server handle once listening; it rejects with a server-error
={:code :eaddrinuse | :eacces ..}= when the port cannot be bound. Options:
=:port= (0 = ephemeral), =:host=, =:backlog=, =:request-timeout-ms= (Node default
300000), =:keep-alive-timeout-ms= (5000), =:headers-timeout-ms= (60000).

On the handle: =core/address= (={:address :family :port}=), =core/listening?=,
=core/connections!= (promise of the open connection count), =core/events= (a
sliding-buffer channel of ={:event :listening | :close | :error | :server-error}=
maps), =core/add-close-hook!= (what =ws/serve!= uses).

** close! — the shutdown choreography
=(core/close! server {:timeout-ms 5000 :ws-close-timeout-ms 2000})= resolves
={:closed true :forced? bool}= (inventory 5.3, verified live on Node 22):

1. every close hook runs with ={:timeout-ms ws-close-timeout-ms}= — the websocket
   layer sends =close(1001, "server shutdown")= to each connection, waits for its
   =close= event up to that deadline, then =terminate()=s the rest (the wrapper's
   deadline wins over ws's 30 s =closeTimeout=; ws guards against a second =close=
   event — verified by the tests);
2. =server.close()= stops accepting; Node ≥ 19 also reaps idle keep-alive
   connections and =closeIdleConnections()= is called for older Nodes;
3. after =:timeout-ms= (an unref'd timer) =closeAllConnections()= cuts stuck
   requests and =:forced?= becomes true;
4. the promise resolves when Node's close callback fired. Closing a server that is
   not listening rejects with ={:code :err-server-not-running}=.

Afterwards the process holds no handle from this server: the smoke build exits by
itself with =process.getActiveResourcesInfo()= empty.

** The request map
Every handler receives one map (inventory 11.3):

={:method :url :original-url :base-url :path :params :query :body :headers
:cookies :signed-cookies :ip :ips :protocol :secure? :host :hostname :subdomains
:xhr? :http-version :remote-address :remote-port :accepts :accepts-encodings
:accepts-charsets :accepts-languages :content-type :content-length :route :app-env
:transport}= plus whatever earlier handlers merged with =route/continue=.

- Header names are lower-case kebab keywords in both directions (=:content-type=);
  values are untouched (=set-cookie= is a vector).
- User JSON (=:body=, =:query=, route params) is keywordised as spelled, never
  re-cased (=maxAge= stays =:maxAge=).
- =:cookies= is parsed from the =Cookie= header without cookie-parser; with an app
  =:cookie-secret=, =s:=-prefixed values move to =:signed-cookies= (verified with
  Node crypto, byte-compatible with =cookie-signature=; a tampered value is
  =false=); =j:= JSON cookies are decoded.
- Negotiation helpers take the map: =core/accepts?=, =core/is?=, =core/range=,
  =core/fresh?= / =core/stale?= (evaluated against the response headers you intend
  to send). =core/with-raw= reaches the Node objects for caller-mounted middleware.

** The response map
A handler returns =nil= (not mine → =next()=), a flow-control sentinel (chapter
[[*Routing as data][Routing as data]]), a response map, or a promise of one of those. Response keys
(inventory 11.4):

| Key | Effect |
|-----+--------|
| =:status= | default 200 (204 for =:end=) |
| =:headers= | kebab map; vectors are multi-valued headers |
| =:body= | string → =send=; map / vector / set (or =:json true=) → JSON; Buffer → binary; Node Readable → piped (streaming); nil → empty |
| =:type= | content type (=:json=, ="text/plain"=) |
| =:cookies= / =:clear-cookies= | vectors of ={:name :value :max-age :http-only? :secure? :same-site :signed? ..}= |
| =:vary= =:links= =:attachment= | =res.vary= / =res.links= / =res.attachment= |
| =:redirect= | ="/x"= or ={:url :status}= (default 302) |
| =:send-file= | ={:path :root ..}= (always pass =:root=; traversal answers 403) |
| =:download= | ={:path :filename :root ..}= |
| =:format= | ={:json (fn [req]) :html .. :default ..}= (=res.format=, 406 otherwise) |
| =:end= | end without a body (204) |

Exactly one of the body keys may be present; a malformed map (unknown key, two
body keys, bad status) is a server bug and renders as 500
(=:express-cljs/server-error {:code :invalid-response}=).

Streaming: =(core/readable-from ["chunk" buffer ..])= builds a Readable without
interop; any Readable is piped with =application/octet-stream= unless =:type= says
otherwise; a stream error before headers goes to the error chain, afterwards the
connection is destroyed.

Static files: =(route/static "/static" "/abs/root" {:dotfiles :ignore :max-age "1d"})=
or =(mw/static root opts)= in a =:use= slot; misses fall through to the wrapper's
404; dotfiles are ignored by default.

* Routing as data
Two equivalent input forms, freely mixed (=express-cljs.route=, pure — every
validation error is an argument-error before any Express call):

*Table form* — a map keyed by method / kind. Maps are unordered, so the table
derives Express's registration order: kinds run =:param= → =:use= → =:routers= →
method routes → =:resource= → =:error=, and within the method routes paths are
sorted by *specificity* (segment by segment: literal < parameter < optional group
< wildcard; a strict prefix first; equal shapes by path string; a specific method
before =:all=; RegExps last). =/users/me= therefore always precedes =/users/:id=.

#+begin_src clojure
{:param   {"id" (fn [req value] (route/continue {:user (load value)}))}
 :use     [(mw/json) ["/api" auth-mw]]
 :routers [{:mount "/admin" :opts {:merge-params? true} :routes {...}}]
 :get     {"/users/me" me  "/users/:id" user  "/files/*splat" [mw handler]}
 :post    {"/users" create}
 :resource {"/things" {:get list :post create}}     ; every other method → 405 + Allow
 :error   [(fn [err req] nil)]}
#+end_src

*Ordered form* — =(route/routes entry ...)= or a plain vector, registered exactly
in source order: =route/get post put patch delete head options query all=,
=route/use=, =route/router=, =route/resource=, =route/static=, =route/param=,
=route/error=, tuples =[:get "/p" h]= / =[:use "/p" mw]=, nested bundles and tables.

Paths use Express 5 / path-to-regexp 8 syntax: =:id= params, ={/:id}= optional
groups, =/*splat= named wildcards (a vector of segments), RegExp paths.
=route/check-path= rejects the three Express 4 spellings with a clear message.

*Flow control* — return values instead of =next= callbacks:
- =nil= → =next()=;
- =(route/continue {:user u} {:x-header v})= → =next()= while merging keys into
  the request map every later handler sees (and setting response headers now);
- =(route/next-route)= / =(route/next-router)= → Express =next('route')= /
  =next('router')=.

*Mounts* — =(route/router "/admin" {:merge-params? true :case-sensitive? .. :strict? ..} entries..)=
mounts an Express Router: =:url= / =:path= are relative to the mount, =:base-url=
keeps the prefix. Handler chains are vectors. =route/upstream= wraps a
caller-supplied Express middleware function, =route/error-handler= an arity-4
handler (chapter [[*Error handling][Error handling]]). =route/plan-paths= prints the registration table
of a compiled plan; =route/compile= is the pure compiler =core/app= runs.

* Middleware helpers
Descriptors for Express's built-ins (validated option maps, instantiated by the
binding): =mw/json=, =mw/urlencoded=, =mw/text=, =mw/raw= (body-parser 2.3:
=:limit= default ="100kb"=, =:strict?=, =:inflate?=, =:type=, =:verify=,
=:reviver= ...) and =mw/static= (serve-static 2.2). Malformed JSON answers 400
=:parse-failed=, an over-limit body 413 =:too-large=, a non-matching content type
is skipped silently (=:body nil=, pitfall 9.8).

=mw/request-id= is an Express-layer helper that continues with =:request-id= in the
request map and echoes the header.

Ring-style wrappers over =(fn [req] -> response | nil | promise)= — they never see
=req= / =res= and report their own failures as rejected promises:

| Wrapper | Does |
|---------+------|
| =mw/wrap-json= | forces JSON bodies out; refuses non-JSON request bodies with 415 |
| =mw/wrap-timing= | adds =x-response-time= |
| =mw/wrap-logging= | one log line per request through =:log= |
| =mw/wrap-errors->http-error= | converts foreign errors to http-errors with a controlled message |
| =mw/wrap-require-header= | 400 when a header is missing / fails =:pred= |
| =mw/wrap-bearer-auth= | =Authorization: Bearer= → =:verify= → =:auth= in the request map, 401 with =WWW-Authenticate= |
| =mw/wrap-cors= | CORS headers as data, preflight 204 |
| =mw/compose= / =mw/wrap-when= | composition |

* WebSockets
** serve!
=(ws/serve! server opts)= attaches one websocket endpoint to a listening server
handle and returns the ws-server value synchronously. The wrapper binds ONE Node
=upgrade= listener per =http.Server= that dispatches by pathname across every
=serve!= on that server and answers a raw HTTP 404 for the rest (Node accepts every
upgrade once a listener exists, inventory 2.3). Options:

| Option | Default | Meaning |
|--------+---------+---------|
| =:path= | ="/ws"= | string, set of strings, or predicate of the pathname |
| =:authenticate= | — | =(fn [upgrade-map] -> ctx | promise | nil)=: nil / false → HTTP 401 before the handshake; a thrown http-error → its status; other throws → 500; a map becomes the connection's =:ctx= |
| =:max-payload= | 1 MiB | over-limit frames close the peer with 1009 (pitfall 9.10) |
| =:keepalive-ms= | 30000 | ping interval (=false= disables); peers that missed a pong are =terminate()=d; the interval is unref'd |
| =:protocols= | — | vector of accepted subprotocol names (first client-offered accepted one wins) or =(fn [offered upgrade-map])= |
| =:handshake-headers= | — | =(fn [upgrade-map] -> header map)= added to the 101 response (a =Set-Cookie=, for instance) |
| =:per-message-deflate= | off | boolean or kebab option map |
| =:close-timeout-ms= | 2000 | the wrapper's per-socket close deadline (then =terminate()=) |
| =:max-buffered-bytes= | 8 MiB | =send!= rejects with =:backpressure= above it |
| =:message-buffer= | 64 | IN channel size; a full buffer pauses the socket |
| =:decode= | — | =:json= parses text frames eagerly (=:json= / =:json-error= on the message) |
| =:shutdown-code= / =:shutdown-reason= | 1001 / ="server shutdown"= | what =close!= sends |
| =:max-buffered-chunks= =:max-fragments= =:allow-synchronous-events= =:auto-pong= | ws defaults | passthrough |

The upgrade request map is built by =core/upgrade-request->map=: the raw
=IncomingMessage= gets Express's request prototype (what =app.handle= does), so
=:ip=, =:query=, =:cookies= / =:signed-cookies=, =:host=, negotiation and the
trust-proxy rules are exactly those of a route handler, with =:transport :ws= and
no body.

** Connection maps and channels
A connection map is handed out for every accepted socket:
={:id :ctx :remote-addr :remote-port :ip :headers :protocol (:ws | :wss)
:subprotocol :upgrade <request map> :in <chan> :out <chan> :opened-at :server-id}=.
Its metadata carries the socket, so every operation needs only the map.

- =(ws/messages conn)= — the IN channel: ={:type :text :data "…"}= or ={:type
  :binary :data <Buffer>}= (text is decoded; a Buffer sent by the peer arrives as a
  binary frame, pitfall 9.21). Closed when the socket closes; closing it yourself
  unsubscribes. When its buffer is full the socket is paused until the consumer
  takes (receive backpressure).
- =(ws/out conn)= — the OUT channel: everything put on it goes through =send!= in
  order.
- =(ws/send! conn data)= → promise of ={:bytes n}=: a string is a text frame, a
  Buffer / Uint8Array / ArrayBuffer a binary frame, ={:text s}= / ={:binary b}= /
  ={:json v}= explicit envelopes, any other value JSON. =ws/send-json!= and
  =ws/send-binary!= are the explicit spellings. Rejections: ={:code :closed}=,
  ={:code :backpressure :buffered-amount n}=.
- =(ws/close! conn code reason {:timeout-ms ..})= → promise of the close event
  ={:code :reason :forced?}=; codes are validated first (1000..1014 minus
  1004/1005/1006, or 3000..4999; reason ≤ 123 bytes) and reported as
  =:invalid-close-code= / =:invalid-close-reason= ws-errors. =ws/terminate!=
  destroys the socket (both sides see 1006). =(ws/closed conn)= is the same promise
  for anyone.
- =(ws/ping! conn data? opts)= → promise of the round-trip milliseconds (ws
  answers pings automatically on both sides).
- =ws/ready-state=, =ws/open?=, =ws/buffered-amount=, =ws/ctx=, =ws/upgrade=.

Message JSON: =ws/parse-json= / =ws/json= (keys as spelled; a ws-error
=:invalid-json= on malformed input) and =ws/->json=.

** Registry, events, topics, broadcast
- =(ws/connections wsv)= — a sliding-buffer channel of ={:event :open :conn c}=,
  ={:event :close :conn c :code :reason :forced?}=, ={:event :error :conn c
  :error e}= (also handshake / auth failures with =:conn nil=). Consume promptly or
  use the lossless callbacks =ws/on-open!= / =ws/on-close!= (each returns an
  unsubscribe fn).
- =ws/conns=, =ws/conn-count=, =ws/conn-by-id=.
- Topics (rooms are a wrapper concept, inventory 6.10): =(ws/join! wsv conn
  "room:1")=, =ws/leave!=, =(ws/topics wsv conn)=, =(ws/topic->conns wsv topic)=; a
  closing connection leaves every topic.
- =(ws/broadcast! wsv data)= to all, =(ws/broadcast! wsv topic-or-conns data
  {:except conn})= to a topic / a collection; =ws/emit!= is the topic spelling. They
  resolve ={:sent n :failed n :errors [..]}= — a closed peer never rejects a
  broadcast.

** Close codes and errors
| Code | Who / when |
|------+------------|
| 1000 | normal (=close!= default) |
| 1001 | =core/close!= / =ws/stop!= shutdown |
| 1002 / 1007 | ws receiver on a framing / UTF-8 violation |
| 1006 | =terminate!=, keepalive termination, and what the SERVER-side close event reports after a receiver error |
| 1009 | what the CLIENT sees after a =:max-payload= violation (uncertainty 10.2, settled by the tests and the smoke) |
| 3000–3002 | reserved by the RPC layer (3001 = =:strict?= protocol violation) |
| 4000–4999 | application codes; reasons round-trip |

Socket errors arrive as ={:event :error}= with a ws-error whose =:code= is the
kebab =WS_ERR_*= name (=:unsupported-message-length=) and, for receiver errors,
=:close-code= = what the peer receives (=ws/ws-error-close-codes=). The close event
of a connection that errored carries the error under =:error=.

** Keepalive and liveness
The keepalive interval (README pattern of ws: mark, ping, terminate the silent) is
one unref'd =setInterval= per ws-server, cleared by =stop!=. =ws/keepalive-stats=
reports ={:pings :terminated}=. Nothing in the layer keeps the process alive after
=core/close!=: the smoke build's exit hook prints an empty active-resource list.

** stop! and the shutdown
=serve!= registers a =core/add-close-hook!=, so =core/close!= runs the choreography
of chapter [[*close! — the shutdown choreography][close!]]. =(ws/stop! wsv {:timeout-ms ..})= runs it alone (the HTTP
server keeps serving; upgrades to the path get a 404 again) and resolves
={:closed n :terminated n}=; it is idempotent.

** Client side
=(ws/connect! "ws://host/path" {:headers .. :protocols .. :max-payload ..
:timeout-ms 5000 :decode :json})= resolves with a connection map that works with the
same functions (=:client? true=, =:url=, =:subprotocol=, =:handshake-headers=, and an
=:events= channel via =ws/events=). A handshake refused with an HTTP status rejects
with ={:code :unexpected-response :status 401}=. The tests and the smoke are its
first users; so is =rpc/client=.

* The RPC layer
** Registry
#+begin_src clojure
(def methods
  (rpc/registry
    {"math/add"  (fn [{:keys [a b]} _ctx] (+ a b))
     "users/get" {:fn (fn [{:keys [id]} {:keys [user]}]
                        (when-not user (throw (rpc/error :unauthorized "login first")))
                        (db/user! id))                       ; a promise is fine
                  :doc "one user" :timeout-ms 5000}}
    {:introspection? true}))                                 ; adds rpc.methods
#+end_src
Names are non-empty strings; =rpc.*= is reserved. Built-ins: =rpc.ping= (answers
={:pong true}=, =:ping? false= removes it) and, opt-in, =rpc.methods= (a vector of
={:name :doc}=). =rpc/methods= and =rpc/method= introspect a registry value; the
same value is passed to =http-routes= and =serve-ws!=.

Methods are =(fn [params ctx] -> result | promise)=. =params= is the frame's params
(a map with keys as spelled, a vector, or nil). Throw =(rpc/error code message
data)= for a chosen JSON-RPC code; an argument-error becomes =-32602=; an
http-error 401 / 403 becomes =-32001= / =-32002=; anything else =-32603= with the
message hidden unless =:expose-errors?=. A method's =:timeout-ms= (or the dispatch
option) turns a slow call into =-32003=.

** Context injection
| Transport | ctx seen by the method |
|-----------+------------------------|
| HTTP | ={:transport :http :request req-map :notify! nil}= merged with the =:context= fn's result, then =:id :method :notification? :params= |
| ws | the connection's =:ctx= (the =:authenticate= result), the =:context= fn's result, then ={:transport :ws :conn conn :notify! f :id :method :notification? :params}= |

** Frames
Text frames and the =POST /rpc= body / response body are identical JSON-RPC 2.0
documents; batches (arrays) are rejected with =-32600= and =data.batch? true=
(uncertainty 10.13; the =:batch?= option is a reserved marker that only accepts
=false=). Pure helpers: =rpc/request-frame=, =rpc/notification-frame=,
=rpc/response-frame=, =rpc/error-frame=, the predicates =rpc/request?=
=rpc/notification?= =rpc/response?= =rpc/error-response?=, =rpc/frame-id=,
=rpc/check-frame= (validation), =rpc/error->frame= / =rpc/frame->error=.

#+begin_src json
{"jsonrpc":"2.0","id":1,"method":"math/add","params":{"a":1,"b":2}}
{"jsonrpc":"2.0","id":1,"result":3}
{"jsonrpc":"2.0","id":2,"error":{"code":-32601,"message":"method not found: x","data":{"method":"x"}}}
{"jsonrpc":"2.0","method":"jobs/progress","params":{"id":3,"pct":50}}      ← notification (either direction)
{"jsonrpc":"2.0","id":null,"error":{"code":-32700,"message":"Parse error"}}
#+end_src

** Error codes
| Wrapper code | JSON-RPC | HTTP status with =:status-map?= | Produced by |
|--------------+----------+---------------------------------+-------------|
| =:parse-error= | -32700 | 400 (always) | malformed JSON (HTTP body / ws text frame), id null |
| =:invalid-request= | -32600 | 400 (always) | not an object, wrong =jsonrpc=, bad method / params / id, batch, binary frame |
| =:method-not-found= | -32601 | 404 | unknown method |
| =:invalid-params= | -32602 | 400 | =(rpc/error :invalid-params ..)=, argument-error |
| =:internal-error= | -32603 | 500 | any other throw / rejection (message hidden unless =:expose-errors?=) |
| =:unauthorized= / =:forbidden= | -32001 / -32002 | 401 / 403 | =(rpc/error ..)= or http-error 401 / 403 |
| =:timeout= | -32003 | 504 | =:timeout-ms= exceeded |
| =:application= | -32000 | 500 | =(rpc/error :application ..)=, other http-errors (=data.status=) |

** Dispatch
=(rpc/call! registry frame ctx opts)= is the one dispatcher both transports use:
promise of the response frame, or nil for a notification (never answered — its
errors go to =:on-error= only). Options: =:timeout-ms=, =:expose-errors?=,
=:on-error (fn [err ctx])=, =:batch?= (marker).

** HTTP: http-routes
=(rpc/http-routes methods {:path "/rpc" :context (fn [req]) :limit "256kb"
:status-map? false})= returns route entries to splice into =core/app=: a
=route/resource= answering POST (other methods → 405 with =Allow=) behind a json body
parser (non-strict, so scalars reach frame validation as -32600) and an error entry
that turns body-parser failures into JSON-RPC transport frames.

| Situation | HTTP status | Body |
|-----------+-------------+------|
| result or method error | 200 | result / error frame — the transport status is independent of the RPC outcome (inventory 7.2) |
| method error with =:status-map? true= (or a ={code status}= map) | the table above | the same error frame |
| notification | 204 | empty |
| malformed JSON | 400 | -32700 frame, id null (a client fault; the body stays a valid JSON-RPC frame so one client code path suffices — the 2011 HTTP-transport draft's 500 was not followed) |
| invalid request / batch | 400 | -32600 frame |
| body over =:limit= | 413 | -32600 frame, =data.reason "body too large"= |
| wrong / missing content type | 415 | -32600 frame |
| a =:context= fn throwing an http-error | that status | the wrapper's error body (chapter [[*Error handling][Error handling]]) |

** Websockets: serve-ws!
=(rpc/serve-ws! wsv methods {:context (fn [conn]) :strict? false :on-open
:on-close :timeout-ms :expose-errors? :on-error})= serves the registry on every
connection of a =ws/serve!= endpoint: frames are dispatched concurrently (a slow
method never blocks the next frame), request frames are answered on the same
connection with the echoed id, notifications are dispatched and not answered,
malformed JSON gets a -32700 frame with id null (or, with =:strict?=, the socket
is closed with 3001), binary frames -32600. It owns the IN channel of every
connection (use another endpoint for raw frames) and returns ={:ws-server
:registry :stop!}=.

** Notifications — the streaming primitive
=(rpc/notify! conn "events/tick" params)= sends a server → client notification;
=(rpc/broadcast-notify! wsv target method params)= to all / a topic / a list. A
method streams by calling the =:notify!= of its ctx (nil over HTTP — check
=:transport=) with the request =:id= in the params and returns the final result
(inventory 7.6). Client → server notifications are frames without =id=.

** Client
=(rpc/client conn {:timeout-ms 10000 :on-notification f :id-prefix "req-"})= over
any connection map returns ={:call! (fn [method params?]) :notify! :notifications
<chan> :pending :close!}=: ids are counters, error frames reject with
=rpc/frame->error= (keyword =:code=, =:data=), a missing answer rejects with
=:timeout= (timers cancelled on arrival), and every pending call rejects with a
ws-error =:closed= when the connection closes.

* Error handling
** Taxonomy
Every error the library raises or normalises is an =ex-info= with =:type=
(=util/error-data=, =util/error-type=, =util/error-status=):

| Type | Data | Rendered as |
|------+------+-------------|
| =:express-cljs/http-error= | =:status :message :expose? :headers :body :reason :cause= | the status; message when =:expose?= (default true below 500) |
| =:express-cljs/server-error= | =:code :message :op= | promise rejections (listen / close) or 500 (=:invalid-response=) |
| =:express-cljs/ws-error= | =:code :close-code :conn-id :reason :cause= | =send!= / =close!= rejections, ={:event :error}= |
| =:express-cljs/rpc-error= | =:code :message :data :id= | JSON-RPC error object |
| =:express-cljs/argument-error= | validation before any upstream call | thrown synchronously; 400 inside a handler; -32602 inside a method |

=core/->error= normalises foreign values: a JS Error with a 4xx / 5xx =status=
(body-parser, serve-static, =res.format=) becomes an http-error with =:reason=
from =err.type= (=:parse-failed=, =:too-large=, ...), other JS Errors become
server-errors with the JS =code=, strings and falsy rejections too.

** The chain and arity-4 handlers
A handler's synchronous throw, rejected promise or thrown non-Error all reach
Express's error chain as one ex-info (the adapter catches first; Express 5's own
forwarding is the second net). Error handlers are =(fn [err req] -> response | nil
| promise)= registered as arity-4 middleware where they appear: in a table's
=:error= slot, with =(route/error "/api" f)=, or app-wide with the =:error-handler=
option (run before the renderer). =nil= passes the error on, a response map
answers, a throw replaces the error.

Express tells an error handler from a request handler by =fn.length= alone
(=router/lib/layer.js=: while an error is in the pipeline, a layer whose function
has any length other than 4 is skipped silently). Closure's advanced
optimizations drop a function's unused trailing parameters, so a four-parameter
ClojureScript =fn= that never calls =next= — the wrapper's final renderer — would
compile to a 3-parameter function under =:advanced= and every error would reach
Express's own HTML error page instead. The wrapper therefore pins =length= to 4
on every error middleware it builds (=Object.defineProperty=; =length= is
configurable), and the suite asserts the lengths of the compiled layer functions
under both optimization levels it runs.

The wrapper's final renderer (=util/error-response=, pure) answers
={:error {:status :message :reason}}= as JSON when the client accepts JSON (or sent
JSON), else =text/plain= =<status> <message>=, with =X-Content-Type-Options:
nosniff=; foreign messages are shown only outside production (=:expose-errors?=).
Every rendered error is emitted on =core/events= as ={:event :error :error e
:status :method :path}= and passed to =:on-error= when given. The 404 layer
(=core/not-found=) lets =OPTIONS= through so Express's automatic =Allow= answer
works.

* Design decisions
- *Express 5.2.1, not 4.x* (inventory 1): the only line receiving features;
  path-to-regexp 8 syntax; native async handler rejection forwarding (the wrapper
  still catches first).
- *Plain ws in noServer mode, express-ws rejected* (inventory 2): express-ws pins
  ws 7, monkeypatches the Router prototype, owns the upgrade event, and can only
  refuse a client after the 101. The wrapper's own upgrade listener authenticates
  before the handshake with real HTTP statuses and shares the server with any
  number of endpoints.
- *Two binding namespaces, not one.* The inventory planned all interop in =core=;
  the ws phase kept the =ws=-package interop in its own binding namespace
  (=express-cljs.ws=) with the same house style, and =core= grew the one Express
  seam it needs (=core/upgrade-request->map=). =route=, =middleware=, =rpc=, =util=
  stay interop-free.
- *JSON-RPC 2.0, single request, notifications, no batch* (inventory 7.1): any
  existing client speaks it; batches add ordering / partial-failure semantics for no
  benefit on a persistent socket. One =POST /rpc= endpoint rather than per-method
  routes; HTTP 200 for method errors with an opt-in status map.
- *Parse errors over HTTP are 400 with a -32700 body*: a client fault, and one
  frame-shaped body for every outcome.
- *Return-value sentinels instead of =next= callbacks* (=route/continue=,
  =next-route=, =next-router=): handlers stay pure functions of the request map;
  request enrichment is explicit data.
- *Specificity ordering for table routes* (pitfall 9.30): a map has no source
  order, so the table form sorts literal < param < optional < wildcard per segment;
  the ordered form is registered verbatim.
- *Lower-case kebab header keywords both ways* (uncertainty 10.1); user JSON is
  never re-cased.
- *=fresh?= as a helper, not a map key* (uncertainty 10.6) — and the Node =fetch=
  pitfall: undici adds =Cache-Control: no-cache= to any request carrying a
  conditional header, so =fresh= reports stale; send an explicit =Cache-Control=
  from the client or use =http.get= (pitfall 9.27).
- *Connections channel is sliding, hooks are lossless*: events are optional to
  consume (like =core/events=), so the channel drops the oldest under pressure;
  =ws/on-open!= / =ws/on-close!= exist for code that must not miss a connection
  (the RPC layer uses them).
- *The wrapper's deadline wins over ws's =closeTimeout=* (uncertainty 10.17):
  =close!= arms an unref'd timer and =terminate()=s; ws guards against a second
  close event — verified by =close-terminates-an-unresponsive-client-once=.
- *Keepalive timers are unref'd* (email-cljs precedent, inventory 6.7): an idle
  process exits on its own; the smoke proves it.
- *Promesa 12.0.1 with a vendored one-line patch.* Promesa 12's ClojureScript
  promise implementation (=promesa/impl/promise.js=, =processNextTick=) lets a
  synchronous throw inside one =p/do= / =p/let= body flip the drain state for every
  later continuation queued on its shared null-promise singleton in the same
  microtask drain; those continuations then resolve with =nil= without running.
  Any two concurrent handlers where one throws could silently skip the other
  (found by the websocket RPC tests, reproduced with three lines of promesa,
  pinned by =util-test/promesa-drain-is-not-poisoned-by-a-throwing-body=).
  =src/promesa/impl/promise.js= is a copy of the upstream file that re-reads the
  promise's state per task; the source path precedes the jar on the classpath, so
  it shadows the jar's copy for the library and for =:local/root= consumers.
  Promesa 11.0.678 drains correctly but changes other semantics (four existing
  tests fail on it), so the patch was preferred over a downgrade; remove it when
  upstream ships a fix.
- *A paused ws socket never emits =close=* (its receiver stops draining): the
  tests resume before awaiting a close; production code should =terminate!=
  instead of pausing a socket it intends to close.
